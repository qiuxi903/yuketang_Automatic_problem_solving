# VIP 分支方案：付费做题平台（主分支零污染）

## Context

当前项目是雨课堂自动化做题平台（Vue3 前端 25173 + Spring Boot 后端 28080 + Python agent/matcher/collector，单仓库单 main 分支，已有邀请码体系和管理后台）。用户要在独立分支上加 VIP 付费能力：**按日期付费解锁（一个日期付一次钱永久可用）+ 月卡无限做题 + 注册送 1 次免费体验额度（后台可调）+ 雨课堂账号 1:1 绑定（防帮他人做题）+ 后台发放优惠码/免费额度/折扣活动 + 精美付费页**。main 保持免费版且本地文件不动；VIP 版同样开源（推 GitHub VIP 分支）。

已确认的决策：
- **支付渠道抽象层三渠道全建**（后台可切换，手动确认永远兜底）：
  1. `LISTEN` 免签监听（主力）：动态金额（价格+随机分尾数）→ 用户扫个人收款码支付 → **电脑端监听工具直接读微信/支付宝桌面客户端窗口里的收款消息**（不依赖 Windows 系统通知）自动回调 → 订单秒到账，零人工零资质零备案；
  2. `MANUAL` 手动兜底：后台订单管理一键确认/拒单；
  3. `XUNHU` 虎皮椒个人支付接口骨架：密钥填 `local.yml` 即启用（无凭证标注 NOT RUN）。
- **新用户注册送 1 次免费额度**（后台可加/减）。
- **本地隔离**：在 `G:\project\做题` 内建 `做题-vip` 子目录作 git worktree（挂 VIP 分支），用 `.git/info/exclude`（.git 内部文件，**不改 main 任何被跟踪文件**）把该目录从 main 的 status 排除。

## 关键现状（探索结论）

- 后端 `com.ykt.platform`：邀请码三件套（`InviteCode`/`InviteUse`/`InviteService`+`AdminInviteController`，悲观锁防超用）= 优惠码的照抄模板；`SecurityConfig` 路径级规则；`ddl-auto: update`；H2 `jdbc:h2:file:./data/ykt`（VIP 改 `ykt-vip` 即数据隔离）；配置链 `application.yml` + `optional:local.yml`。
- **做题日期 = `Task.batch`**（"10-30"），闸门点：`TaskService.create()/setBatch()/agentNext()`。
- **绑定挂载点现成**：Agent 登录成功已回传 `session-status{yktName}`（`worker.py` → `SessionService.updateStatus`），账号名读取在 `ykt_driver.ykt_name()`；`_wait_login_with_qr`（worker.py L192-197）有「读不到账号名也放行」兜底，VIP 分支必须 fail-closed。
- 前端：付费校验收口 `store/console.ts` 的 `startTask/continueTask/startRedoTask` + `api/client.ts` 拦截器；管理页模板照 `AdminInvites.vue`；设计系统 v2（琥珀 `--amber` 做 VIP 金、完整暗色令牌、768px 断点）。

## 实施步骤（全部在 `G:\project\做题\做题-vip` worktree、VIP 分支上）

### Phase 0 · 分支与隔离
1. `git worktree add -b VIP 做题-vip main`
2. `.git/info/exclude` 追加 `/做题-vip/`
3. `git push -u origin VIP`

### Phase 1 · 后端 VIP 域（8 实体 + 3 控制器，金额一律用分 int）

新实体（ddl-auto 建表）：
- `VipSettings`（单例 id=1）：datePassPriceFen、monthPriceFen、monthDays(30)、payChannel(LISTEN/MANUAL/XUNHU)、payQrWechat/payQrAlipay(TEXT base64)、payNote、listenToken；启动种子（默认单日 ¥3 / 月卡 ¥29）
- `VipActivity`：name、discountPercent(80=8折)、appliesTo、startsAt、endsAt、enabled
- `VipOrder`：orderNo、userId、kind(DATE_PASS/MONTH_CARD)、targetBatch、originalFen、discountFen、payableFen（=价格−最优折扣+随机尾数 1~99 分，`suffixFen` 单独存）、status(CREATED/PAID/CANCELLED/REJECTED)、payChannel、couponCode、remark、adminRemark、paidAt、expiresAt(10 分钟)
- `VipEntitlement`：userId、kind(DATE/MONTH)、targetBatch、expiresAt、sourceOrderNo、grantedBy、revoked
- `VipCoupon`+`VipCouponUse`（仿 InviteCode）：code(YH-XXXX-XXXX)、kind(DISCOUNT/DATE_PASS/MONTH_PASS/QUOTA)、valuePercent、quotaCount、maxUses、perUserLimit、usedCount、disabled、expiresAt
- `RainBinding`：userId(unique)、yktName(unique)、boundAt；`VipAccount`：userId(unique)、freeQuota

服务与控制器：
- `VipService` + `VipController` `/api/vip/**`：`GET status`（月卡到期/额度/已解锁批次/绑定账号）、`GET products`（价格+活动折扣+批次解锁态）、`POST orders`（套优惠码/活动取最优折扣）、`GET orders`、`POST orders/{no}/claim-paid`、`POST orders/{no}/cancel`、`POST redeem`、`POST unlock-quota`
- `AdminVipController` `/api/admin/vip/**`：订单列表/确认/拒单/**粘贴收款文本快速核销**；优惠码 CRUD+批量；活动 CRUD；用户权益发放（月卡/额度/单日/撤销）；绑定列表+解绑；设置读写
- `PayNotifyController` `/api/pay/notify`（permitAll + listenToken）：`{channel, amountFen, raw}` → 金额精确匹配 + 10 分钟窗口 + CREATED → 自动核销（撞单取最早+告警）；`/api/pay/notify/xunhu` 验签核销

闸门与绑定（改现有文件）：
- `TaskService.create()/setBatch()/agentNext()` 注入 `VipService.checkBatchAccess`：月卡在期或 DATE 权益→放行，否则抛 `VipRequiredException` → advice 返 **402** `{code, batch, datePriceFen, monthPriceFen}`；ADMIN 或 `ykt.vip.enforce=false` 放行
- `SessionService.updateStatus` + `TaskService.create`(reuseYkt)：绑定 1:1 双端查重 → 违规置 session `REJECTED`+message；`ykt.vip.bind-required=false` 可关
- `AuthService.register`：建 `VipAccount(freeQuota=ykt.vip.free-quota-on-register 默认1)`
- `application.yml`：datasource 改 `./data/ykt-vip`；`ykt.vip.*`（VipProperties：enforce、bind-required、free-quota-on-register、xunhu 密钥留 local.yml）

### Phase 2 · 前端（2 个新页面 + 小改）

- **`views/VipPage.vue` 路由 `/vip`**（独立全屏，requiresAuth）——琥珀金渐变 hero（参照 Login.vue 渐变手法）、权益状态卡（月卡剩余天数/已解锁日期/额度/绑定账号）、双定价卡（单日解锁=选日期；月卡=推荐角标+划线价）、优惠码输入、兑换码入口、支付弹层（收款码+精确金额+10 分钟倒计时+3s 轮询，PAID→成功动效）、历史订单；`var()` 自动适配暗色，移动端单列
- **`views/admin/AdminVip.vue`** 路由 `admin-vip`：el-tabs 四页签（订单[确认/拒单/粘贴文本核销]、优惠码、活动与支付设置[价格/收款码/渠道切换]、用户权益[发月卡/调额度/解绑]），手机端卡片双视图
- 小改：`api/client.ts` 拦 402 → 弹「该日期需解锁」→ 跳 `/vip?batch=xx`（覆盖全部开始做题入口）；`ConsoleLayout.vue` 顶栏 VIP 徽章+入口；`router/index.ts`、`AdminLayout.vue navItems`；`api/vip.ts`、`types/index.ts`；`store/console.ts` 开始做题前轻量预检已解锁态（未解锁→「消耗 1 次免费额度？」→`unlock-quota`，否则去 /vip）

### Phase 3 · `pay-listener/` 电脑端监听工具（读窗口，不读系统通知）

**多策略，按配置自动选择，针对用户实际微信版本现场校准**（本地环境可直接实测）：
- **策略 A（默认）：UIA 窗口读取** — Python `uiautomation` 轮询微信桌面客户端窗口的无障碍树（1~2s），监控「微信支付/收款助手」会话的新消息，正则提取收款金额 → 回调。纯读窗口不注入不碰进程，零封号风险；支付宝 PC 客户端同理配置关键词
- **策略 B（兜底）：截图 + OCR** — UIA 树读不到（微信 4.x 新框架可能弱化无障碍支持）时，对微信窗口定时截图，RapidOCR（onnxruntime 离线）识别「收款 X.XX 元」文本 → 回调
- **策略 C（可选，默认关）：wcferry 消息钩子** — 微信 3.9.x 版本可用、实时性最好，但属注入方案有封号风险，仅作为可选项写清楚
- 实现：`listener.py`（策略调度+去重+重试+自检模式）、`config.ini`（backend 地址+listenToken+策略+关键词/正则，gitignore，附 example）、README（策略选择指南）
- **交付前用用户本机微信实测校准 selector**，保证策略 A 或 B 至少一条真实跑通

### Phase 4 · Agent 绑定 fail-closed（最小 diff）

- `worker.py _wait_login_with_qr`：去掉「读不到账号名也放行」→ 延长重试，超时如实回 `yktName=null`（后端 REJECTED）
- `worker.py` 处理 `status=REJECTED` → 中止任务，前端登录步显示原因（账号与绑定不符/已被他人绑定）
