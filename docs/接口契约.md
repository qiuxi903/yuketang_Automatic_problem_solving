# 接口契约（P0）

> 前后端、Agent、matcher、collector 之间的统一约定。P0 阶段 backend 用 H2 内存库与内存队列，
> 预留 MySQL / Redis 实现位；接口路径与字段以本文件为准，各端不得自行改名。

## 一、约定

- 统一前缀 `/api`，请求与响应均为 JSON（二维码图片除外）。
- 鉴权：平台账号 JWT，请求头 `Authorization: Bearer <token>`。
- 时间：ISO-8601 字符串；得分统一为字符串 `"48/48"` 形式。
- 状态枚举：
  - 会话 session：`WAITING_SCAN` `SCANNED` `EXPIRED` `CLOSED`
  - 任务 task：`PENDING` `RUNNING` `WAITING_BATCH` `PAUSED` `CANCELLED` `SUCCESS` `FAILED`
  - 明细 task_item：`PENDING` `ANSWERING` `SUBMITTED` `FAILED` `SKIPPED` `REUSED`

## 二、认证

| 方法 | 路径 | 入参 | 出参 |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | `{username, password}` | `{id, username}` |
| POST | `/api/auth/login` | `{username, password}` | `{token, username, role}` |

`role` 取值 `USER` / `ADMIN`，前端据此显示管理后台入口，JWT 亦携带该角色用于服务端鉴权。
首次启动会自动引导管理员账号（`ykt.admin.username` / `ykt.admin.password`，默认 `admin` / `admin123`）。

## 三、雨课堂会话

| 方法 | 路径 | 入参 | 出参 |
| --- | --- | --- | --- |
| POST | `/api/sessions` | `{mode?}` | `{sessionId, status, qrcode}` |
| GET | `/api/sessions/{id}` | - | `SessionDetail` |
| DELETE | `/api/sessions/{id}` | - | `{ok}` |

`qrcode` 为 dataURL 字符串（`data:image/png;base64,...`），未生成时为 `null`。

`SessionDetail` 结构（供前端展示扫码状态、批次/模式与截止时间）：

```json
{
  "sessionId": 1,
  "status": "WAITING_SCAN",
  "qrcode": "data:image/png;base64,...",
  "yktName": null,
  "batch": null,
  "mode": "answer",
  "expireAt": "2026-10-03T10:05:00Z",
  "createdAt": "2026-10-03T10:00:00Z"
}
```

`expireAt` 为二维码有效期（5 分钟），前端据此渲染倒计时；`yktName` 为扫码后回传的雨课堂账号名。
`batch` 在批次后置流程下初始为 `null`，用户确认批次后由后端同步回填；`mode` 在模式后置流程下初始为默认 `answer`，确认后回填为用户所选值。

## 四、课程与试卷

| 方法 | 路径 | 入参 | 出参 |
| --- | --- | --- | --- |
| GET | `/api/papers` | - | `{batches:[{batch,date,papersCount,questions,papers:[{name,file,questions,score}]}], summary}`（来自 manifest.json） |
| GET | `/api/papers/{batch}/{name}/answers` | - | `{batch, paper, questions, answers:[{seq, stem, answer}]}` |
| GET | `/api/papers/answers` | `batch?` `paper?` `date?` | `AnswersBundle` |
| GET | `/api/papers/export` | `batch?` `paper?` `date?` | `text/markdown` 附件 |

答案获取按查询参数决定范围，优先级 `paper > batch > date`，`scope` 取 `SINGLE`（单个卷子）/`BATCH`（整批获取）/`DATE`（按日期获取）：

- `?batch=10-01&paper=202601` → `SINGLE`，1 套卷子
- `?batch=10-01` → `BATCH`，该批次全部卷子
- `?date=2026-10-01` → `DATE`，该日期（批次）全部卷子

`AnswersBundle` 结构（`papers[].answers` 与单卷接口的 `answers` 同结构）：

```json
{
  "scope": "BATCH",
  "batch": "10-01",
  "paper": null,
  "date": null,
  "papersCount": 30,
  "questions": 1626,
  "papers": [
    {"batch": "10-01", "paper": "202601", "date": "2026-10-01", "questions": 50,
     "answers": [{"seq": 1, "stem": "网络拓扑结构中，环形结构的传输特点是 ( )。", "answer": "单向传输"}]}
  ],
  "summary": {"batches": 1, "papers": 30, "questions": 1626}
}
```

`GET /api/papers/export` 与 `/api/papers/answers` 入参一致，返回 UTF-8 的 Markdown 附件；响应头同时给出 ASCII 兜底名与 RFC 5987 编码名，保证中文文件名可下载：
`Content-Disposition: attachment; filename="answers.md"; filename*=UTF-8''answers-10-01.md`。导出内容含范围标题、批次、导出时间（本地时间 `yyyy-MM-dd HH:mm:ss`）与各卷题干 + 正确答案。

> 该组接口挂在 `/api/papers/**` 下，按 Spring Security 规则需要平台 JWT（`Authorization: Bearer <token>`）。

## 五、任务

批次后置 + 模式后置：`POST /api/tasks` 时 `batch` 与 `mode` 均可省略。任务先进入扫码登录流程，Agent 登录后回传账号实际作业清单，
任务转入 `WAITING_BATCH`；前端据此展示候选批次（按与账号作业的命中覆盖率排序），用户确认批次并选择作答模式
（自动作答 `answer` / 答案采集 `collect`）后，再由 Agent 按批次与模式作答。

采答案的零消耗口径（三种模式的既定行为，Agent 侧已硬约束）：

- **已交卷的试卷**：直接打开结果页（`https://examination.xuetangx.com/result/{examId}?isFrom=2`，或详情页「查看试卷」新标签）只读取正确答案，**不进入答题、不交卷**，因此不消耗作答次数；明细记为 `SUBMITTED`。
- **未交卷的试卷（采集模式）**：不取答案，直接跳过并回传提示「该试卷尚未作答，无法获取答案；请先完成作答，完成后再采集」，明细记为 `SKIPPED`。
- **答案库已有该卷答案（含其它账号采集）**：直接复用答案库、不重复抓取，明细记为 `REUSED`（终端态，计入已完成）。
- 硬门禁：采集/复用模式下 `driver.submit_forbidden=True`，任何 `submit()` 调用都会直接抛错，从机制上杜绝重复消耗作答次数。
- 自动作答模式下首次作答成功后，会「顺带」把抓到的正确答案写回答案库，供后续其它账号直接复用。

| 方法 | 路径 | 入参 | 出参 |
| --- | --- | --- | --- |
| POST | `/api/tasks` | `{batch?, mode?, sessionId}` | `{taskId, status, totalPaper}` |
| GET | `/api/tasks` | - | `[Task]` |
| GET | `/api/tasks/{id}` | - | `Task` |
| GET | `/api/tasks/{id}/batch-options` | - | `BatchOptions` |
| POST | `/api/tasks/{id}/batch` | `{batch, mode?}` | `{ok}` |
| POST | `/api/tasks/{id}/pause` | - | `{ok}` |
| POST | `/api/tasks/{id}/resume` | - | `{ok}` |
| POST | `/api/tasks/{id}/interrupt` | - | `{ok}` |
| DELETE | `/api/tasks/{id}` | - | `{ok}` |
| GET | `/api/tasks/{id}/frame` | - | `TaskFrame` |
| WS | `/ws/tasks/{id}` | - | 推送 `Task` 快照 |

中断与删除（均按 `userId` 校验归属，越权返回 404/403）：
- `POST /api/tasks/{id}/interrupt`：仅 `PENDING`/`RUNNING`/`WAITING_BATCH`/`PAUSED` 可中断，成功后任务进入终端态 `CANCELLED`（前端展示「已中断」），并移出待领取队列；其余状态返回 409。中断后 Agent 的迟到回调（报题/进度/完成）会被幂等忽略，不会复活任务。
- `DELETE /api/tasks/{id}`：硬删除，连同 `task_item` 明细一并移除，不可恢复；任务不存在时返回 404。删除后 `GET /api/tasks` 不再包含该任务。

`Task` 结构（`batch` 在确认批次前为 `null`，`mode` 在确认前为默认 `answer`、确认后为所选值；`course`/`papers` 为 Agent 登录后回传的账号上下文，任务全程保留以便前端常驻展示）：

```json
{
  "taskId": 1,
  "createdAt": "2026-10-05T23:07:54Z",
  "batch": "10-01",
  "mode": "answer",
  "status": "RUNNING",
  "sessionId": 1,
  "totalPaper": 30,
  "donePaper": 4,
  "currentPaper": "202605",
  "currentSeq": 12,
  "currentTotal": 48,
  "score": "192/192",
  "items": [
    {"paper": "202601", "examId": "4623903", "status": "SUBMITTED", "score": "50/50", "error": null,
     "questions": [{"seq": 1, "stem": "下列时间复杂度最小的是？", "options": ["O(1)", "O(n)", "O(n²)", "O(log n)"]}]}
  ],
  "message": "正在作答 202605",
  "course": "数据结构（2026春）",
  "papers": [{"name": "202605", "questionCount": 48, "fullScore": 50, "score": "48/50", "status": "已交卷"}]
}
```

`items[].questions` 为该试卷的题目完整信息（题干 + 选项），由 Agent 实时抓题回传（答案库 md 不含选项）。前端据此在答题区展示完整题目；未抓到时为空数组。

`createdAt` 为任务创建时间，前端「我的任务」列表按此展示。`GET /api/tasks` 返回**当前登录账号**的全部任务（按 `userId` 过滤，倒序）；前端据此在刷新后恢复该账号最近的未结束任务，任务绑定账号而非浏览器会话。

`TaskFrame` 结构（`GET /api/tasks/{id}/frame`，供前端「浏览器模式」展示雨课堂原始页面）：

```json
{
  "image": "data:image/jpeg;base64,...",
  "url": "https://ykt.io/web/student/exam/...",
  "updatedAt": 1791202721000
}
```

`image` 为 Agent 定时回传的页面截图 dataURL（约 2 秒一帧），后端内存缓存最近一帧；尚无截图时三个字段均为 `null`。
`updatedAt` 为毫秒时间戳，前端据此展示画面新鲜度。

`BatchOptions` 结构（`GET /api/tasks/{id}/batch-options`，仅在 `WAITING_BATCH` 状态有意义）：

```json
{
  "papers": [{"name": "202605", "questionCount": 48, "fullScore": 50, "score": "48/50", "status": "已交卷"}],
  "options": [
    {"batch": "10-01", "total": 30, "questions": 1440, "matched": 6, "percent": 20,
     "matchedPapers": ["202605"], "missedPapers": ["202601"]}
  ],
  "recommended": "10-01"
}
```

`papers` 为 Agent 登录后抓到的账号实际作业；`options` 按命中数降序，`percent` 为命中覆盖率；
`recommended` 为命中数大于 0 的首个批次，无命中时为 `null`。命中判定与 Agent 一致：账号作业名包含答案库试卷名即视为命中。

## 十、兜底答题（agent → backend）

| 方法 | 路径 | 入参 | 出参 |
| --- | --- | --- | --- |
| POST | `/api/answer/fallback` | `{batch, paper, questions:[{seq, stem, options[]}]}` | `{answers:[{seq, answer}]}` |

未启用、未配置或调用失败时返回 `{"answers":[]}`，Agent 跳过这些题。Agent 拿到答案文本后再经 matcher `/match` 映射为选项索引。

被配置的接口需实现如下约定（`Content-Type: application/json`，如配置了 apiKey 则带 `Authorization: Bearer <apiKey>`）：

```json
// 请求
{"batch": "09-24", "paper": "硬件2010", "questions": [{"seq": 1, "stem": "...", "options": ["...", "..."]}]}
// 响应
{"answers": [{"seq": 1, "answer": "选项文本或字母"}]}
```

响应也兼容 `answers: ["A", "B", ...]` 的纯数组形式。

## 十一·二、答案社区（/api/community/**）

需登录（JWT）。社区数据来源：Agent 回传答案接口 `POST /api/agent/tasks/{id}/answers` 新增 `source` 字段——`collect`（结果页新采集，自动发布为贡献）与 `reuse`（复用库内答案，不计贡献）；同一任务同一试卷只记一条贡献。

| 方法 | 路径 | 入参 | 出参 |
| --- | --- | --- | --- |
| GET | `/api/community/contributions?limit=20` | `limit`（1-50） | `[ContributionView]` |
| GET | `/api/community/search?q=关键词&limit=50` | `q`（必填），`limit`（1-100） | `[SearchHit]` |

```json
// ContributionView
{ "username": "张三", "batch": "10-01", "paper": "202601", "questions": 50, "taskId": 3, "createdAt": "..." }
// SearchHit（按题干/答案包含关键词命中，不分大小写）
{ "batch": "10-01", "paper": "202601", "date": "2026-10-01", "seq": 1, "stem": "……", "answer": "……" }
```

配套前端行为：待确认批次界面若推荐批次 `percent>=100`，前端 10 秒倒计时后自动确认开始（自动做题模式），任何手动操作可取消。

进度口径（2026-10-08 起）：`setBatch` 的 `totalPaper` 与任务明细只按「批次 ∩ 账号实际作业」计算（Agent 只处理账号真实存在的卷子）；Agent 作答时逐题回报 `seq/total`（`click_answers` 逐题回调），采集模式收尾 summary 汇总 新采集/复用/未交卷/失败 套数。

### 重做任务与「取答案未做」（2026-10-08 增补）

- 明细状态新增 `COLLECTED`（取答案未做）：已交卷试卷经结果页只读取到答案、本任务未重做；终端态计入已完成。
- `POST /api/tasks` 入参新增可选 `redoPapers: [卷名]`——重做任务：明细与 totalPaper 只按「重做清单 ∩ 批次」，Agent 只重做清单内的卷子（绕过复用/已交卷规则，直接作答交卷）。
- `Task` 快照新增 `redoPapers`（普通任务为空数组）。
