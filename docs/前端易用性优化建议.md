# 前端易用性优化建议

> 背景：用户反馈「前端问题很大，很难用、难懂」。本文先列出问题诊断与建议，再逐条落地修改。
> 范围：仅前端展示层与文案，不改任何后端接口与业务逻辑。

## 一、问题诊断

通读 `frontend\src` 后，确认以下五个核心问题：

1. **主流程没有引导，三栏空面板让人无从下手**
   新建任务 → 扫码 → 确认批次与模式 → 看进度 → 导出，这条主线散落在三栏、两个弹窗和一个抽屉里。没有任何任务时，左中右三栏各自显示空态，页面不告诉用户「第一步点哪里」。

2. **最关键的一步被藏进了「运行日志」抽屉（严重）**
   扫码成功后进入「选择批次与模式」阶段，候选批次列表竟然渲染在「运行日志」抽屉里（`ControlDeck.vue` 的 log drawer 内），中栏只显示「当前批次：未选择」和确认按钮。用户找不到批次在哪选，流程直接卡死。

3. **术语黑话太多**
   「批次」「会话」「任务令牌 T2·S2」「答案采集」「已复用」等词没有任何解释。用户不知道「批次」是答案库版本号，也不知道「自动作答」和「答案采集」的本质区别是「会不会交卷、消不消耗作答次数」。

4. **右栏信息优先级颠倒**
   「账号与任务」九宫格（令牌、会话创建时间、会话截止等技术字段）占了大量版面，真正要看的「答题卡」被推到需要滚动的位置。任务做完后也没有一个明确的收尾界面（总分、完成套数、导出入口）。

5. **操作按钮无分组无解释**
   运行中状态的 6 个按钮（获取答案、扫码弹窗、重新获取二维码、暂停、导出、关闭会话）平铺在两列网格里，没有按使用场景分组，也没有说明何时该用哪个；「扫码弹窗」这种按钮名让用户不知道点了会发生什么。

## 二、建议与对应修改

### 建议 1：把主流程做成显式步骤条
在工作台顶部加一条流程步骤条：`1 新建任务并扫码 → 2 确认答案库与模式 → 3 自动作答中 → 4 完成导出`，由任务状态自动点亮当前步骤，页面任何时刻都在回答「现在到哪一步、接下来干什么」。
**修改**：新增 `components/console/FlowSteps.vue`，接入 `views/Console.vue`。

### 建议 2：批次选择移回主界面（修复卡点）
「候选批次」从运行日志抽屉移回中栏菜单，扫码成功后直接在中栏选批次、看推荐、选模式、点确认；抽屉回归纯日志。
**修改**：`ControlDeck.vue` 的 `WAITING_BATCH` 分支；推荐批次加「推荐」标记；补充「账号已交卷 X / Y 套」统计帮助选择模式。

### 建议 3：术语白话化 + 就地解释
- 「批次」补充说明为「答案库版本」；模式单选下方解释两种模式的实际后果（自动作答会交卷、消耗次数；只取答案不交卷、零消耗）。
- 状态标签补充悬停提示：如「已复用」解释为「答案库已有该卷答案，直接取用，不再交卷」；「已跳过」解释为「该卷未交过卷，无法直接取答案，需先做题」。
- 操作按钮按场景重命名与分组：「扫码弹窗」→「查看二维码」。
**修改**：`ControlDeck.vue`、`PaperRail.vue`、`utils/status.ts`（新增 `ITEM_HINT`）。

### 建议 4：右栏做减法，突出「进度 + 答题卡」
- 「账号与任务」九宫格折叠为默认收起的「运行详情」，需要排查时再展开。
- 任务结束（完成/失败/中断）时顶部显示总结卡：完成态给总分、完成套数和大号「导出答案」按钮；失败/中断给原因和「再发起一次任务」。
- 右栏头部与顶栏重复的「实时在线」状态去掉（顶栏已有）。
**修改**：`AnswerStage.vue`。

### 建议 5：空态改为引导首页
无任务时三栏不再显示空面板文案，右栏空态改为一句话引导（配合步骤条，指路「点左上按钮开始」），左栏空态改为「扫码登录后这里会显示你账号的全部试卷」。
**修改**：`AnswerStage.vue`、`PaperRail.vue` 空态文案。

## 三、不改的部分

- 不改后端接口、store 的动作逻辑、WebSocket 与轮询机制。
- 不改登录页与管理后台（本次反馈针对做题工作台）。
- 「运行日志」抽屉保留（已按需求收纳），只把误放进去的批次选择移出。

## 四、验证方式

- `vue-tsc --noEmit` 类型检查 + `vite build` 构建通过。
- 启动 `npm run dev` 实测：无任务引导态、步骤条展示、批次选择回到中栏（需后端配合的流程留待实机验证）。
